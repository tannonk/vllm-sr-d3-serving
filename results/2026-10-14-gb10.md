# Benchmark record: d3-flash on a DGX Spark (GB10), 2026-10-14

Every number below was measured on one machine in one session. Raw `/metrics` windows are in
[`raw/`](raw/) (one JSON object per window, produced by `benchmarks/server_window.py`).

## Setup

| | |
| --- | --- |
| Hardware | NVIDIA DGX Spark, GB10 (sm_121), 121.7 GiB unified CPU/GPU memory (273 GB/s), aarch64 |
| Base image | `nvcr.io/nvidia/pytorch:26.01-py3`: torch 2.10.0a0+a36e1d39eb.nv26.01, CUDA 13.1, Triton 3.6.0 |
| Runtime | `vllm-srun` 0.2.0 at `vllm-project/semantic-router@a61d0e9ab109abc6cf1ab3c2201f5dbced2fe8fb` |
| Kernels | `fla-core` 0.5.2, `causal-conv1d` 1.7.0 (compiled, `TORCH_CUDA_ARCH_LIST=12.0`) |
| Model | `vllm-sr/d3-flash` revision `521525effa79469d899a570726547dd7f00da3af`, BF16, 8.39B parameters |
| Workload | role classification of podcast episodes: one `choice` question per person (5 options), <= 8 questions per request, state = podcast + episode title/description (+ few-shot examples) |
| Data | 297 German episodes, 412 people with a name, 380 matched to gold, ~1.9 questions per request, rows of ~600 tokens |

## 1. End-to-end: speed and answers

Wall time of the full client run (`--mode map`, 4 client processes, client retries off, 297 episodes;
~15 s of it is client startup). Same requests in every row.

| Stack | few-shot 0 | few-shot 10 | Speed-up vs shipped (wall / excluding startup) |
| --- | --- | --- | --- |
| Runtime as shipped (exact kernels) | 77 s | 116 s | 1.00x |
| + fused kernels | 58 s | 86 s | 1.33x - 1.35x / 1.42x - 1.44x |
| + fused kernels + FP8 linear layers | 42 s | 62 s | 1.83x - 1.87x / 2.15x - 2.30x |

Failed requests: 0 of 432 in every configuration (client retries off, status counters from `/metrics`).

### Answers against the exact-kernel run

| Comparison | People | Role changed | max abs dP | mean abs dP |
| --- | --- | --- | --- | --- |
| fused vs exact, few-shot 0 | 412 | 0 (0.00%) | 0.027 | 0.0007 |
| fused vs exact, few-shot 10 | 412 | 0 (0.00%) | 0.029 | 0.0008 |
| FP8 vs exact, few-shot 0 | 412 | 6 (1.46%) | 0.146 | 0.0049 |
| FP8 vs exact, few-shot 10 | 412 | 7 (1.70%) | 0.299 | 0.0063 |

The changed FP8 predictions were all near-ties (for example `mentioned` 0.54 vs `guest` 0.54 flipping to
`guest`; confidence 0.54 -> 0.54).

### Role accuracy against gold (380 matched people, co-host collapsed into host)

| Stack | few-shot 0 | few-shot 10 |
| --- | --- | --- |
| exact | 0.7921 (301/380) | 0.8053 (306/380) |
| fused | 0.7921 (301/380) | 0.8053 (306/380) |
| fused + FP8 | 0.8053 (306/380) | 0.7974 (303/380) |

FP8 moved +5 and -3 people: noise at this sample size, in both directions.

## 5. The session's starting point (shipped runtime, before any change)

From `/metrics` of a running server, person-role workload:

| Clients | forward busy | tokens/s | rows / tokens per forward | mean queue wait | HTTP 500 |
| --- | --- | --- | --- | --- | --- |
| 1 | ~100% | ~2,920 | 1.65 / ~1,000 | 2 ms | 0 |
| 4 | 97% | ~3,020 | 1.57 / ~1,500 | ~820 ms | ~4.7% (146 of ~3,100) |

The 500s were `TypeError: varlen_attn() got an unexpected keyword argument 'scale'`: the runtime's packed forward
passes `scale=` and `enable_gqa=` to `torch.nn.attention.varlen.varlen_attn`, which torch 2.10.0a0 does not accept.
The launcher removes that kernel when the signature does not match. `windows_fused_2procs_fs0.jsonl` is from before
the fix and shows two such 500s (the client retried them).

## 6. Reference points from upstream

| Source | Number | Context |
| --- | --- | --- |
| d3-flash model card | 95-99 requests/s | one-question short text, batching on, one AMD MI325X |
| vllm-srun record (`decision3-lanes-packing.md`) | d3-mini text-only 85.6 requests/s | 330-token ticket, 1 question, MI325X |
| This record | 3.4-3.8 requests/s, ~6,500 tokens/s | ~1,200 tokens per request (1.9 questions of ~620 tokens), GB10 |

The difference is hardware (an MI325X has roughly an order of magnitude more BF16 compute than the GB10) and
request size, not configuration: the profile above shows the GPU busy ~100% of the time.
